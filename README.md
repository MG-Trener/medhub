# Anamio

Anamio — кабинет врача и AI-ассистент для заполнения листа консультации. Создано в рамках хакатона medhub. Vue 3, FastAPI, PostgreSQL, Docker Compose. Собственная база данных, без зависимости от БД ЛИС.

Название приложения — **Anamio** (отсылка к анамнезу). Домен, репозиторий и технические идентификаторы medhub сохранены для совместимости с текущим развёртыванием.

## Локальный запуск

Нужен запущенный Docker Desktop (Linux containers).

```powershell
./scripts/setup.ps1
docker compose up --build -d
```

UI: http://localhost:5173. OpenAPI / Swagger: http://localhost:5173/api/docs. API напрямую: http://localhost:8010. PostgreSQL наружу не публикуется.

`setup.ps1` создаёт `.env` с отдельными случайными ключами шифрования, поискового индекса, паролем PostgreSQL и кодом приглашения. Существующий `.env` не перезаписывается. Для регистрации врача используйте `REGISTRATION_CODE` из своего `.env`.

Для локальной демонстрации с вымышленными данными можно создать окружение через `./scripts/setup.ps1 -Demo` (либо установить `DEMO_MODE=true` в уже существующем `.env`) и выполнить:

```powershell
docker compose exec api python -m app.seed_demo
```

Демонстрационный логин: `doctor@medhub.local`. Пароль задаётся только через `DEMO_PASSWORD` в закрытом `.env`; `setup.ps1 -Demo` генерирует его случайно. Если `.env` уже существует, задайте пароль самостоятельно и пересоздайте API/worker перед первоначальным запуском seed. Повторный seed не меняет пароль существующей учётной записи. Скрипт не работает при `DEMO_MODE=false`. Перед публичным развёртыванием создайте отдельную production-БД и ключи; не переносите demo-учётную запись.

Изменения Vue: `cd frontend; pnpm install; pnpm dev`. В dev-режиме Vite перенаправляет `/api` на `127.0.0.1:8010`. При этом Compose UI, который использует тот же порт 5173, нужно остановить: `docker compose stop ui`.

## Что реализовано

- Регистрация и вход по паролю; вход/регистрация по ЭЦП через NCALayer + SIGEX; QR-подписание в eGov Mobile через SIGEX.
- Пациенты с UUID, ИИН, ФИО, датой рождения, телефоном, внешним ID МИС. Поиск по полному ИИН и префиксам частей ФИО.
- Отдельные согласия на запись, облачную обработку обезличенного текста и облачное распознавание проверенного аудио.
- Карта пациента, история приёмов, ручной лист консультации, запись с выбором микрофона и сохранением deviceId в браузере. Никакие медицинские данные в localStorage не сохраняются.
- Персистентная очередь заданий PostgreSQL, отдельный worker. В этой версии один worker; масштабирование требует lease/heartbeat вместо восстановления всех `running` при старте.
- Распознавание после остановки записи: faster-whisper + pyannote локально или на вашем удалённом ASR, либо OpenAI с разделением говорящих. Реальное streaming-распознавание в эту версию не включено.
- Редактирование реплик, определение ролей врач/пациент/медсестра локальной/облачной LLM, ручное исправление ролей.
- Черновик полей: жалобы, анамнез, объективный статус, диагноз, рекомендации. Генерация запускается отдельной кнопкой, не подтверждает лист за врача.
- Подтверждение врачом, API чтения для МИС и пример исходящего клиента с ключом идемпотентности.

## Удалённый ПК с моделями

Пошаговая инструкция и отдельный Compose: [deploy/gpu/README.md](deploy/gpu/README.md).

Основная конфигурация Anamio для собственного GPU-ПК:

```dotenv
ASR_PROVIDER=self_hosted
ASR_URL=http://<VPN-IP-GPU-ПК>:8090
ASR_API_KEY=<ASR_SERVICE_TOKEN с GPU-ПК>
INSTALL_LOCAL_AI=false
LLM_PROVIDER=ollama
LLM_URL=http://<VPN-IP-GPU-ПК>:11434
LLM_MODEL=qwen3:8b
LLM_IS_CLOUD=false
```

Затем `docker compose up -d --force-recreate api worker`. Распознавание поддерживает до трёх голосов; роли не выводятся из номеров голосов — их определяет LLM, врач проверяет. Таймкоды слов сопоставляются с диаризацией по максимальному пересечению интервалов.

Текущий ноутбук не скачивает веса и не выполняет GPU-инференс. Для распознавания выбран OpenAI; нужен серверный API-ключ. `LLM_PROVIDER=disabled`: генерация листа и определение медицинских ролей требуют отдельного подключения LLM, ручное заполнение доступно.

## OpenAI: распознавание с разделением говорящих

Включён адаптер `gpt-4o-transcribe-diarize`: `/v1/audio/transcriptions`, `response_format=diarized_json`, `chunking_strategy=auto`. Он возвращает текст, таймкоды и номера голосов. Врач/пациент/медсестра — смысловые роли, они по-прежнему назначаются отдельно. Модель `gpt-transcribe` рекомендована OpenAI для обычной транскрипции, но не возвращает нужные кабинету speaker-сегменты; для текущего сценария выбрана модель с диаризацией.

Документация: [speech-to-text](https://developers.openai.com/api/docs/guides/speech-to-text), [gpt-4o-transcribe-diarize](https://developers.openai.com/api/docs/models/gpt-4o-transcribe-diarize).

На сервере отредактируйте `/opt/medhub/shared/app.env` (root, права 600):

```dotenv
ASR_PROVIDER=openai
OPENAI_API_KEY=<ключ проекта OpenAI API>
```

Затем:

```bash
systemctl restart medhub-api medhub-worker
```

Локально ключ в `C:\Users\ASUSvivobook\PycharmProjects\medhub\.env`, затем `docker compose up -d --force-recreate --no-deps api worker`. Ключ не нужен во Vue, не используйте префикс `VITE_`. Подписка ChatGPT не заменяет доступ/квоту OpenAI API. Не коммитьте ключ. `.env.production` — локальная копия, её редактирование само по себе не меняет работающий сервер.

В карте пациента отметьте согласие на запись и отдельное согласие на передачу **исходной записи в OpenAI, включая возможные персональные и медицинские данные**. Ранее данное согласие на обезличенный текст/аудио это разрешение не заменяет. Без него отправка заблокирована в API и worker. Если согласие отозвано до обработки, запрос не уйдёт; если уже во время внешнего запроса, отправку отменить нельзя, но результат не сохраняется. Старым пациентам новое согласие автоматически не выставляется.

Сначала запишите разговор, остановите запись, нажмите «Распознать запись». Временная копия перед отправкой сжимается ffmpeg в mono MP3 48 kbps (24 kHz) без обрезки. Лимит после сжатия — 24 MB, достаточно примерно для часа. Автоматических повторных платных запросов нет. Ошибки ключа/квоты показываются без содержимого ответа провайдера. Локальная исходная запись удаляется после попытки обработки; маскированное аудио шифруется и хранится по обычным правилам Anamio. Это не управляет хранением данных у OpenAI.

При отсутствии ключа интерфейс показывает «Ожидает OPENAI_API_KEY». Реальные запросы требуют ключа и пока не проверены; тесты используют подмену HTTP-ответов и синтетические данные.

## Конфиденциальность и облако

ФИО, ИИН, контакты, тексты, листы и профили шифруются на уровне приложения (Fernet). Для поиска хранятся HMAC-индексы. UUID, служебные связи, времена, статусы и внешний ID МИС не зашифрованы. Сохраните `ENCRYPTION_KEY` и `INDEX_KEY` отдельно от резервной копии БД: без них данные/поиск не восстановить. Смена ключей требует миграции.

Пароли — Argon2; браузерные сессии — случайные отзываемые HttpOnly-cookie с TTL 8 часов. Для browser writes проверяются Origin и служебный CSRF-header. Данные изолированы по врачу; общей клинической команды и ролевой модели организации пока нет. Регистрация в обычном режиме требует кода приглашения. Действия записываются в аудит без ПДн/подписей/ключей.

Первое распознавание выполняется локально/на доверенном сервере либо в OpenAI при отдельном согласии на передачу исходной записи. В режиме OpenAI маскирование происходит уже после получения ответа, поэтому не защищает исходную запись от облачного провайдера. Обнаруженные ИИН, телефоны, email, сведения из карточки и простые паттерны адресов/имён заменяются маркерами. Это эвристики, не гарантия полной анонимизации, особенно для произнесённых словами чисел, третьих лиц, склонений и казахского языка.

Worker также создаёт WAV с заглушёнными целыми репликами, в которых найдены ПДн, сохраняя таймкоды. Врач может дополнительно заглушить реплики во вкладке «Маскирование» и прослушать результат. Исходное аудио удаляется после попытки обработки. Обезличенная версия хранится зашифрованно до `AUDIO_RETENTION_HOURS` (24 часа); читать её может только владелец при действующем согласии. Если локальное распознавание/ffmpeg не сработали, облако не используется автоматически.

Для облачной LLM с OpenAI-совместимым API:

```dotenv
LLM_PROVIDER=openai_compatible
LLM_URL=https://api.openai.com/v1
LLM_API_KEY=<секрет>
LLM_MODEL=<модель с JSON-output>
LLM_IS_CLOUD=true
```

Для второго прохода облачного ASR, который принимает OpenAI-совместимый `/audio/transcriptions` с `verbose_json` и таймкодами:

```dotenv
CLOUD_ASR_URL=https://api.openai.com/v1
CLOUD_ASR_API_KEY=<секрет>
CLOUD_ASR_MODEL=whisper-1
```

Для этого второго прохода отправка разрешается лишь после первого распознавания и маскирования, отдельного согласия пациента на cloud audio, проверки текста и явного подтверждения врачом прослушивания обезличенной записи. Отправляется только заглушённый WAV, до 24 MiB. Голос сам по себе может идентифицировать человека: обработка облаком требует решения владельца данных, а маскирование не эквивалентно гарантированной деидентификации. Не выдавайте проект за сертифицированную медицинскую систему.

## SIGEX

NCALayer подписывает nonce, полученный backend из SIGEX; SIGEX проверяет подпись через `/api/auth` с `external=true`. QR использует `/api/egovQr`, подпись возвращается через закрытые серверные capability-ссылки. Сессия привязана к HttpOnly-cookie браузера, ограничена по времени и погашается один раз. Аккаунт врача связывается с проверенным ИИН, а не с присланным браузером ФИО.

Для QR требуется доступ компьютера/server к SIGEX и eGov Mobile пользователя; для ЭЦП — NCALayer на компьютере врача и действующий ключ. Сквозная подпись реальной ЭЦП ещё не проверена. Тесты проверяют отказ при ошибке SIGEX, привязку к браузеру и запрет повторного использования. Официальный контракт: [SIGEX auth](https://sigex.kz/support/developers/api-auth/), [SIGEX eGov QR](https://sigex.kz/support/developers/api-egov-basic/).

## API МИС

Получите ключ во вкладке «Настройки». Хранится только HMAC ключа; он показывается один раз, новый выпуск отзывает предыдущий. Передавайте `Authorization: Bearer <ключ>`.

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/v1/integration/encounters?since=0&offset=0&limit=50` | Подтверждённые приёмы врача, фильтр по Unix-времени подтверждения |
| GET | `/api/v1/integration/encounters?patient_id=<UUID>` | Приёмы конкретного пациента |
| GET | `/api/v1/integration/encounters/{UUID}` | Карточка пациента, поля листа, расшифровка и роли |
| POST | `/api/v1/encounters/{UUID}/send-to-mis` | Серверная отправка после подтверждения; сессия врача и `{ "version": N }` |

Ответ списка: `items` и `next_offset`. `schema_version=1.0`. UUID приёма и `version` позволяют обновлять данные. Повторный запрос исходящей отправки использует `Idempotency-Key: <UUID>:<version>`; получатель должен обрабатывать его. При редактировании подтверждение снимается до повторной проверки. API-ключ МИС не даёт доступ к browser endpoints.

Пример вымышленной МИС: `examples/mock_mis.py`. Самостоятельный клиент: `examples/mis_client.py`. Запуск в отдельном Python-окружении с зависимостями backend:

```powershell
# MIS_TOKEN задайте в окружении отдельно, не коммитьте.
python -m uvicorn examples.mock_mis:app --host 127.0.0.1 --port 8020 --no-access-log
```

Клиент берёт `MEDHUB_API_KEY`, `MIS_TOKEN` из окружения, `MEDHUB_URL` по умолчанию `http://localhost:8010`, `MIS_URL` по умолчанию `http://localhost:8020/v1/consultations`:

```powershell
python examples/mis_client.py <UUID-подтверждённого-приёма>
```

Приёмник демонстрационный, хранит только контрольные суммы в памяти, теряет их при перезапуске. Для встроенной кнопки отправки задайте backend-переменные `MIS_URL` и `MIS_TOKEN`. При удалённой МИС нужен HTTPS либо закрытый VPN.

## ИИН врача и вход через SIGEX

При регистрации по email обязателен ИИН: ровно 12 цифр ASCII. ИИН хранится в зашифрованном профиле, для поиска используется уникальный HMAC `identity_hash` от `IIN` + 12 цифр. Один ИИН соответствует одному кабинету; повторная регистрация через email или SIGEX не создаёт второй кабинет.

ЭЦП / NCALayer и QR / eGov Mobile используют общий механизм: SIGEX проверяет подпись серверного nonce, затем backend берёт подтверждённый `userId=IIN…` и ищет учётную запись по тому же HMAC. При входе неизвестный ИИН не создаёт аккаунт. При регистрации по подписи ИИН из формы должен совпасть с подтверждённым ИИН. После успешной проверки профиль получает `iin_verified=true`; имя и email существующего кабинета сохраняются.

Для ранее созданного кабинета без ИИН: войдите привычным способом, откройте «Настройки → ИИН и вход по ЭЦП» и выполните привязку собственной ЭЦП через NCALayer. Она требует действующей исходной сессии и проверенной подписи. Замена уже записанного ИИН, присвоение занятого ИИН и автоматическое объединение кабинетов запрещены. QR-вход после такой привязки открывает тот же кабинет. ИИН не извлекается из имени, email или непроверенных данных браузера. Изменение использует существующий уникальный столбец; миграция и массовое изменение старых учётных записей не нужны.

## Сервер medhub.ych.kz

Развёртывание на `77.37.65.54` выполняется без Docker через systemd, по запросу владельца:

- Релиз: `/opt/medhub/releases/20260930-4`, активная ссылка: `/opt/medhub/current`.
- Vue: `/opt/medhub/current/ui`, отдаётся Nginx по HTTPS.
- `medhub-api.service`: FastAPI от пользователя `medhub`, только `127.0.0.1:8010`.
- `medhub-worker.service`: отдельный обработчик заданий от пользователя `medhub`.
- Python-окружение: `/opt/medhub/current/.venv`, Python 3.11; версии зависимостей из `requirements.lock`.
- Настройки: `/opt/medhub/shared/app.env` (доступ только root); аудио: `/opt/medhub/shared/audio` (доступ только medhub).
- База: отдельная `medhub` в Supabase, роль `medhub_app`, SSL. База `postgres` существующего приложения не используется. Пул ограничен двумя соединениями на процесс, без дополнительных соединений сверх лимита.
- HTTPS Let's Encrypt с автоматическим продлением; HTTP перенаправляется на HTTPS.

`DEMO_MODE=false`, защищённые cookies, регистрация по приглашению. Общедоступная демо-учётная запись не создаётся. Код приглашения сохранён локально в игнорируемом `artifacts/production-access.txt`; копия настроек и ключей — в `.env.production`. Не теряйте ключи шифрования при следующих релизах.

ASR и LLM пока выключены. Для подключения удалённого ПК задайте адреса и ключи в серверном `app.env` согласно [инструкции GPU-ПК](deploy/gpu/README.md), затем перезапустите обе службы. Запись и генерация будут доступны после настройки провайдеров; ручное заполнение доступно сразу.

```sh
systemctl status medhub-api medhub-worker
systemctl restart medhub-api medhub-worker
journalctl -u medhub-api -u medhub-worker -n 100 --no-pager
curl --fail https://medhub.ych.kz/api/health
```

Файлы служб: [deploy/systemd](deploy/systemd). Nginx: [deploy/nginx/medhub.https.conf](deploy/nginx/medhub.https.conf). Скрипт первого релиза: [deploy/install-service-release.sh](deploy/install-service-release.sh). Обновление: `sh deploy/update-service-release.sh <release-id>` после загрузки исходников и UI в соответствующий каталог. Скрипт сохраняет настройки и возвращает предыдущий релиз при неудачном запуске; миграции данных автоматически не откатываются. Изменение конфигурации Nginx применяется после `nginx -t` через `systemctl reload nginx`.

Для следующего релиза: загрузить исходники и собранный UI в новый каталог `releases`, подготовить его `.venv`, остановить worker на время миграций, проверить целевую БД `medhub`, применить Alembic, переключить `current` и перезапустить службы. Проверить HTTPS/API. Для отката переключить `current` на предыдущий совместимый релиз; откат кода не отменяет миграции и изменения данных. Сохраняйте предыдущие релизы, резервные копии БД и ключей.

Docker-упаковка сохранена для UMC: `compose.yaml` для локального запуска и `deploy/compose.production.yaml` как альтернативная конфигурация. Docker установлен на сервере, но его службы выключены: стандартный сетевой мост несовместим с текущей конфигурацией OpenVZ/nftables. Для текущего запуска он не нужен. Другой сайт `healthcore.ych.kz` работает независимо.

## Проверки

### Предварительное заключение ИИ

Кнопка «Заполнить лист и заключение ИИ» формирует из обезличенной расшифровки отдельное поле `fields.ai_conclusion`. В расшифровку можно внести текст вручную. Модель обобщает сведения и отмечает недостаток данных; поле `diagnosis` предназначено для диагноза врача. Повторная генерация сохраняет уже внесённый диагноз. Заключение остаётся черновиком до проверки врачом.

В интерфейсе и в обоих направлениях интеграции с МИС передаётся серверная пометка `encounter.ai_notice`: `is_diagnosis=false`, `requires_doctor_review=true` и текст «Данное предварительное заключение ИИ не является диагнозом. Врач обязан проверить его и несёт окончательную ответственность за диагноз, назначения и медицинские решения». Пометка сохраняется и после подтверждения врачом; изменить её через PATCH нельзя. Заключение хранится в существующем зашифрованном поле листа, миграция БД не требуется. Для генерации нужна настроенная LLM; без неё вымышленные результаты не подставляются.

```powershell
cd backend
python -m pytest -q
cd ../frontend
pnpm install --frozen-lockfile
pnpm build
```

Тесты проверяют права доступа, согласия, шифрование, конфликты версий, маскирование аудио, отсутствие выдачи черновиков МИС, идемпотентную повторную отправку, CSRF, закрытие сессии и SIGEX. Они работают на SQLite; рабочий Compose использует PostgreSQL и Alembic. Реальные модели, GPU и подпись ЭЦП требуют отдельной сквозной проверки на целевом оборудовании.
