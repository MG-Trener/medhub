# Кабинет пациента

URL `/patient`. Отдельный cookie `medhub_patient_session`, отдельные аккаунты, Argon2 пароли, HMAC логины, зашифрованные профили и анкеты. Пациентский аккаунт не открывает врачебную медкарту, не подтверждает ИИН и не служит ЭЦП.

Врач создаёт одноразовое приглашение сроком 7 дней и задаёт RU/KK сценарий либо использует стандартный анамнез. Токен находится в fragment URL, хранится в БД как HMAC, не попадает в серверный access log и не отправляется третьим сторонам. Ссылка расходуется при создании анкеты; получатель выбирает голосовое и API-согласия отдельно. Кабинет пока только для взрослых ≥18 лет; детский/представительский сценарий требует отдельного согласия и привязки представителя.

Пациент регистрируется заранее, отвечает вручную либо записывает ответы до 25 секунд. Звук идёт только доверенному ASR; временный файл удаляется после распознавания. RU, KK и смешанные ответы сохраняются на исходном языке, затем автоматически обезличиваются перед API LLM. Нажатие «Сохранить и далее» переводит к следующему вопросу. Это разговор по очереди с небольшим ожиданием ASR, а не передача сырого непрерывного микрофона внешнему realtime API.

Сначала обязательные вопросы врача; чувствительный ответ можно пропустить. После сценария LLM выбирает до трёх релевантных уточнений из двуязычного каталога. Произвольные диагнозы, дозировки и новые назначения от модели пациенту не показываются. Если модель или защита ПДн недоступна, исходная анкета сохраняется и может быть отправлена врачу.

Вопросы читаются локальным системным голосом браузера (`localService=true`); внешние браузерные голоса не выбираются. Отсутствие установленного казахского голоса оставляет текстовый вопрос, но не отключает казахский ASR. Полное голосовое озвучивание KK на целевом ПК нужно проверить отдельно или подключить локальный TTS с лицензированной казахской моделью. Это ограничение текущего выпуска, не подтверждённая готовность TTS.

Неотложный вопрос показывается постоянно, явная отметка пациента прекращает анкетирование. Есть узкие дополнительные фразы RU/KK. Это не полный клинический триаж и не система вызова скорой. При резком ухудшении пациенту предлагается самостоятельно звонить 103/112; [официальная информация Казахстана](https://www.gov.kz/situations/55/intro?lang=ru). Автоматического уведомления врача нет.

Отправленную анкету видит только врач приглашения. Он сопоставляет личность с текущим пациентом и переносит анкету один раз в анамнез как «со слов пациента». Анкета не заполняет объективный осмотр, диагноз или лечение. Версии защищают одновременное редактирование, импорт снимает подтверждение клинического документа. Отзыв голосового/API-согласий действует на последующие операции и отменяет сохранение результата начатого анализа при смене версии.

Техническая регистрация пока без проверки email и без самовосстановления пароля. Для закрытого пилота доступ начинается только по одноразовому приглашению, медкарту пациент получить не может. Для публичного промышленного кабинета нужна подтверждённая идентификация/восстановление доступа и организационная процедура поддержки; не заменять её небезопасным сбросом пароля по введённому ИИН.
