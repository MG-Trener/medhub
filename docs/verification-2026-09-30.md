# Проверка Anamio — 30.09.2026

Все облачные проверки выполнены на синтетическом разговоре и вымышленных карточках. Приложенные фото медицинского документа и DOCX в OpenAI не отправлялись. Секреты и результаты с карточками находятся только в игнорируемых локальных файлах.

## Сквозной сценарий

- OpenAI: доступ к модели LLM проверен реальным запросом; `gpt-6-astra` вернул структурированное заключение через Responses API со строгой схемой и `store=false`.
- Синтетический разговор с двумя голосами создан через TTS и загружен через интерфейс. `gpt-4o-transcribe-diarize` вернул 18 реплик с таймкодами; LLM определила врача и пациента, заполнила поля, показатели осмотра, источники и предварительное заключение.
- Через интерфейс исправлена опечатка ASR, выбран J02.9 из справочника, отмечена проверка аллергии, сохранён и утверждён результат. Архив содержит оригинал и версии до/после исправления. Предыдущий утверждённый приём отображается с датой в следующей консультации.
- Отдельная синтетическая учётная запись: регистрация, парольный вход/выход, запрет загрузки без согласия, ручной приём, отсутствие черновика в API МИС, появление после утверждения, отзыв ключа МИС.
- Пример `examples/mis_client.py` дважды передал один утверждённый документ в реально запущенный локальный `examples/mock_mis.py`: HTTP 201, идемпотентность сохранена.
- Автотесты backend покрывают согласия, изоляцию врачей, версии, шифрование, сохранность архивов, ошибки провайдеров, выдачу утверждённых результатов, SIGEX с подменой ответов, строгую схему LLM и поиск МКБ-10. Тест записи проверяет паузу, продолжение и ожидание последнего аудиофрагмента перед отправкой.

## Что взято из предоставленных материалов

- Из референсов: отдельные согласия, реквизиты приёма, маскированный ИИН, первичный/повторный и очный/онлайн формат, разделы консультации, показатели осмотра, редактируемые роли/реплики, диагноз из справочника, явное утверждение врачом.
- Из DOCX: пустое поле означает отсутствие сведений, а не отрицание; источники заполненных полей; отметки проверки; история изменений; напоминания о недостающих сведениях; контекст предыдущего приёма с датой; сохранение расшифровки при сбое LLM; возможность отклонить черновик и заполнить вручную.
- При противоречии с DOCX применены указания пользователя: аудио сохраняется постоянно, разрешены предложения диагнозов для проверки врачом. Это не автоматическое установление диагноза.
- Сайт `sign.umc.org.kz` не открылся полностью: шлюз вернул 502, прямой запрос не подтвердил цепочку TLS. Проверка сертификата не отключалась. Закрытый кабинет и формы UMC не считаются исследованными.

## Границы проверки

- Встроенный браузер не завершил запрос разрешения физического микрофона. Исправлено зависание формы: через 15 секунд появляется понятное сообщение, ручная работа/загрузка снова доступны. Живая запись с аппаратного микрофона требует проверки в браузере врача; пауза/остановка проверены автотестом, облачный конвейер — загруженным аудио.
- Настоящая ЭЦП и подписание eGov Mobile требуют ключа/телефона владельца. Эти финальные действия не имитируются как успешно выполненные.
- Локальные модели не запускались по указанию пользователя.
- Справочник МКБ-10 содержит 14 586 кодов из опубликованного среза 14.04.2021. Не объявляется актуальной редакцией Казахстана/UMC; перед клинической эксплуатацией нужен согласованный справочник клиники.
- Чек-лист полноты не является клинически валидированным контролем назначений, взаимодействий или противопоказаний. Чтение внешней карты МИС, клинические протоколы и соответствие нормативным формам требуют отдельных согласованных контрактов/правил.

## Воспроизводимые локальные проверки

```powershell
cd backend
../.venv/Scripts/python.exe -m pytest -q
cd ../frontend
pnpm test
pnpm build
```

Для живой проверки: создать вымышленного пациента с тестовыми согласиями → начать приём → загрузить синтетическое аудио → «Распознать и заполнить» → проверить поля/источники → выбрать диагноз → отметить проверку → «Утвердить результат приёма». После этого запросить документ через `/api/v1/integration/encounters/{id}` с ключом МИС этого врача.
