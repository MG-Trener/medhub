### Быстрый промежуточный анализ

В профиле `LLM_COMPACT_EXTRACTION=true` промежуточный live-проход локальной LLM возвращает только факты с точными цитатами, вопросы и роли последних голосов. Сервер раскладывает факты по полям и нормализует измерения, включая измерения из объективного осмотра; заявления «диагноз не установлен» и планы врача не превращаются в операции/привычки/анамнез. Пустой промежуточный результат не стирает прежние справочные правки. Полная схема и гипотезы остаются в окончательном анализе и ручной перегенерации. Неизвестные сведения не дополняются по догадке.

Повторная синтетическая проверка после исправлений: русский — **12.02 с**, RU/KK — **10.28 с**, искусственный длинный разговор — **24.00 с**, ручная перегенерация справочного поля — **14.14 с**. Все выбранные структурные/строковые проверки прошли; сохранены аллергия, роли, 120/80, пульс 72 и ручной диагноз. Длинный набор имитирует отдельные метки голосов ASR-фрагментов, а не только два стабильных ID. Эти одиночные измерения не являются p95 и не подтверждают совместную GPU-нагрузку или медицинскую корректность гипотез.

## Следующие этапы до промышленного использования

1. На RTX 3060 12 ГБ обновить **эту ветку**, выполнить [GPU roadmap](local-ai-production.md), установить ASR/диаризацию/GLiNER с manifest. Хранить токены только в локальном секретном env. Проверить `/ready` и синтетический privacy-корпус. До этого не включать API LLM для автоматического приёма.
2. На GPU-ПК уменьшить исходный parallel 4 до 1, начать с контекста 8192; измерить VRAM, p50/p95 и очередь при ASR+NER+LLM. Быстрый проход достиг 10–24 секунд на отдельных текстовых запросах; подтвердить полный голосовой цикл до 30 секунд либо выбрать профиль меньшего размера по врачебному корпусу. Фоновый анализ сохраняет обработку новых фрагментов, но не доказывает этот SLA.
3. С участием врача проверить RU/KK/mixed живую речь, два голоса, препараты/дозы, отрицания, незнакомые имена, числа словами и исправления. Измерить время врача на финальную правку относительно ручного листа. Семантическая связь «цитата → поле», повторные вопросы и справочные гипотезы ещё требуют клинической приёмки.
4. Проверить казахское озвучивание на целевом устройстве. Сейчас выбирается только локальный голос браузера; при отсутствии KK-голоса вопрос остаётся текстовым. Для полностью голосового сценария нужен локальный KK TTS с проверенными правами и качеством.
5. Для публичного кабинета внедрить подтверждённую идентификацию и восстановление доступа, согласования по хранению/срокам/удалению данных и поддержку. Текущий взрослый пациентский поток предназначен для анкет по одноразовому приглашению врача; не открывает карту по заявленному имени/ИИН.
6. На поддерживаемом Docker-хосте собрать оба образа, поднять изолированный Compose, проверить миграцию/перезапуск/backup restore. Выполнить реальную приёмку API МИС с её владельцем; текущий API и идемпотентность проверены синтетическими тестами.
7. После этих проверок оформить решение о клиническом допуске. До него нельзя утверждать, что устранены все слабые стороны, нет пропусков ПДн или продукт готов к самостоятельной диагностике.
