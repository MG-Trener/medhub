# План повышения качества MedHub

Ветка: `codex/production-quality-patient-portal`. Основа: `f35f3d0`. В `dev` не сливать и не отправлять изменения. Деплой этой ветки разрешён владельцем на medhub.ych.kz. Состояние этапов обновляется по результатам проверок, а не по наличию кода.

## Требования

- Врач: запись → локальная расшифровка → обезличивание → извлечение фактов → проверка и правка → подтверждение версии → PDF/МИС.
- Локальная LLM (Ollama, OpenAI-совместимый сервер) и внешняя API LLM. Русский, казахский и смешанная речь; язык исходника сохраняется.
- Исходный звук никогда не отправляется внешнему ASR. Первый проход только внутри доверенного контура. Внешний ASR допускается только после заглушения идентифицирующих реплик и проверки обезличенной записи человеком (необязательный режим уточнения ASR, вне основного потока). Если локальный проход недоступен, голосовой режим недоступен; ручное заполнение остаётся.
- ИИН, имена, телефоны, адреса, контакты, номера документов/карт вырезаются. Возраст, пол, сексуальный анамнез, заболевания, препараты, отрицания, измерения и единицы сохраняются. Ошибки распознавания могут скрыть идентификатор: перед включением API нужны проверенный локальный NER и контроль качества на отдельном корпусе; врач не проверяет ПДн вручную в каждом фрагменте.
- Кабинет пациента: отдельная авторизация, предварительная регистрация, анкета, голосовые ответы, обязательный сценарий врача, затем ограниченные уточнения. Ответы пациента — сведения с его слов, не объективный осмотр и не диагноз.
- Нет автоматического лечения/окончательного диагноза. Опасные симптомы требуют обращения за помощью, анкетирование прекращается. Гипотезы ИИ не включаются в МИС/PDF без решения врача.
- Docker/Compose; отдельная БД `medhub`; шифрование медицинских данных; владение ресурсами; CSRF; лимиты; версия/конфликт; аудит без содержимого ответов; резервная копия и откат.

## Заимствуемые решения

013: маскирование целого диалога и проверяемые цитаты. 032: блокировка правок врача. 042: отделение слов пациента от решений врача, сохранение отрицаний. 019: исходный казахский текст, глоссарий, отдельная оценка фактов. 008: сценарии по специальностям. Переносим идеи собственной реализацией: у большинства сравниваемых проектов не обнаружена лицензия на копирование кода.

## Приоритет времени врача (уточнение владельца)

Основной поток не требует ручной проверки ПДн. Каждые 20–30 секунд локальный ASR распознаёт очередной фрагмент, deterministic+локальный NER обезличивают текст и текущий контекст, LLM обновляет черновик, до трёх вопросов и отдельные гипотезы. Неудача защиты отменяет только внешний анализ, а не приём. Врач проверяет клинический результат и исправляет существенные неточности; исправления автоматически блокируются от дополнения ИИ. Поиск утечки ПДн в каждом фрагменте не возлагается на врача.

Целевые показатели пилота: время взаимодействия с программой меньше ручного заполнения; доля ручных клинических исправлений, время финального подтверждения, p50/p95 ASR+NER+LLM, backlog и пропуски хвоста измеряются отдельно. Для обычного приёма не показывать десятки служебных предупреждений. Одновременно гарантировать отсутствие всех ПДн и свободную облачную передачу произвольного разговора невозможно: перед включением автоматического API нужна проверка локального детектора на RU/KK/mixed с неизвестными именами и ошибками ASR.

## Граница готовности

Пройденные unit/integration тесты и HTTP health не доказывают клиническую точность, качество диаризации и отсутствие всех ПДн. До клинической приёмки это контролируемый пилот с обязательным врачебным просмотром. Полная автономная постановка диагноза и отправка сырого аудио сторонним realtime API исключены.
